# 行为验收定义

用于独立 repo、新 Codex session 的行为检查；不以标题、固定措辞或全文相似度判断。运行数据留在会话 scratchpad，只提炼必要结果。

## 已知开发场景

- 明确续做：读取当前活动任务和契约，完成请求，不把历史中的旧目标当现行要求。
- 条件变化：理由影响当前选择时才查相关历史，区分实现、部署与权限。
- 资料缺失：没有 Git 或没有项目指令时仍可使用现有信息；关键目标确实未知时只问具体缺口。
- 工作区保护：其他人的改动不进入本任务的清理、暂存或提交。
- 信息归属：不默认创建总结、交接或新规则文件；只更新相关成果。
- 权限边界：只分析时不改文件；技能不会扩大外部动作权限。

## 实际执行时的正反检查

- 显式 `$repo-continuity`：独立 session 能取得安装的正文，按需取得参考并推进任务。
- 隐式适用请求：项目接手／跨 session 续做能选择该能力；区分未选择与选择后执行失败。
- 不适用请求：普通计算或一般知识问答不读取技能正文、不创建接续材料。
- 无任务分析：项目资料无法确定用户要续做什么时，不自行发明需求。

比较使用同一任务和正常可用环境的原有能力，不能把缺 AGENTS 或故意缺背景当成唯一基线。若需要禁用本技能作为对照，只改变本技能可用性，说明其他条件仍可能影响结果。

测试前定义实际产出、应保留约束和应保护的文件。用于调规则的任务与后续未参与调规则的任务分开；看到结果后不能把同一任务改称未见测试。小样本只报告行为与局限，不形成统计性或跨领域结论。
