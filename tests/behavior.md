# 行为验收定义

本文保留早期三项技能的手动行为检查定义。全量 14 项制作按用户要求不新增或运行独立 session 对比；新增 11 项只执行格式、内容审阅及安装分发检查，不将下列历史检查外推到它们。

用于独立 repo、新 Codex session 的行为检查；不以标题、固定措辞或全文相似度判断。运行数据留在会话 scratchpad，只提炼必要结果。

## 已知开发场景

- 明确续做：读取当前活动任务和契约，完成请求，不把历史中的旧目标当现行要求。
- 条件变化：理由影响当前选择时才查相关历史，区分实现、部署与权限。
- 资料缺失：没有 Git 或没有项目指令时仍可使用现有信息；关键目标确实未知时只问具体缺口。
- 工作区保护：其他人的改动不进入本任务的清理、暂存或提交。
- 信息归属：不默认创建总结、交接或新规则文件；只更新相关成果。
- 权限边界：只分析时不改文件；技能不会扩大外部动作权限。

## 实际执行时的正反检查

- 显式 `$repo-continuity`：独立 session 能取得安装的正文，按需取得参考并推进任务。
- 隐式适用请求：项目接手／跨 session 续做能选择该能力；区分未选择与选择后执行失败。
- 不适用请求：普通计算或一般知识问答不读取技能正文、不创建接续材料。
- 无任务分析：项目资料无法确定用户要续做什么时，不自行发明需求。

比较使用同一任务和正常可用环境的原有能力，不能把缺 AGENTS 或故意缺背景当成唯一基线。若需要禁用本技能作为对照，只改变本技能可用性，说明其他条件仍可能影响结果。

测试前定义实际产出、应保留约束和应保护的文件。用于调规则的任务与后续未参与调规则的任务分开；看到结果后不能把同一任务改称未见测试。小样本只报告行为与局限，不形成统计性或跨领域结论。

## 变更收尾的行为边界

针对代码已改、相关当前材料尚未同步的请求，检查受影响的配置、文档与活动任务是否完成收尾。区分当前说明里的过程段落与正式历史，保留仍有效的限制、理由和未来任务；遵守不暂存或不提交的明确请求。

合成场景的明确输入包括：工厂默认值变化、单位保持、幂等性理由、正式兼容承诺、其他人的既有改动。实际文档内容需人工判断，不能仅凭文件变化或一组关键词宣称信息归属正确。对照保留同一任务和正常环境，只禁用对应技能。

## 变更影响检查

独立合成项目将 v2 的整数秒改为整数毫秒，字段名和类型不变。评估前确定观察点：分析应覆盖经别名包装的生产者链、消费端单位换算、配置输入语义、无版本持久化记录与回放、当前契约与测试、活动任务；区分需保留秒语义的 v1 与无关动画变量，指出外部消费者未知，不能从局部搜索声称完整兼容。分析请求不应产生文件修改、暂存或提交。

`tests/run_impact_check.py` 运行新 CLI session；`--baseline` 仅禁用该技能，保留正常配置和其他技能。脚本只机械核对文件与 Git 边界，内容须人工按上述语义检查，不能以术语命中计分。原始输出留在指定 scratchpad；用于调规则的样本不能再算独立验收。
