# 迁移计划

将旧状态到目标状态的切换组织为可执行阶段。输入是目标变化、现有数据／消费者及兼容约束；输出是迁移路径、阶段条件和未查明范围，不把源码修改当作迁移完成。

## 取得迁移边界

确定接口／数据／依赖的旧新语义、消费者与生产者、实际版本和有效支持承诺。区分已知清单和未知范围，特别关注跨 repo 使用者、离线客户端、后台任务、旧配置、存量数据与回放路径。

先明确目标与授权，再考虑切换方案；没有环境资料时可以形成条件性计划，但不能编造现网数量、兼容窗口或声称消费者已迁移。关键未知给出具体调查任务，不将整份计划无限阻塞。

## 安排共存与阶段条件

按真实依赖选择版本并存、适配、逐批转换、一次切换等适用路径，说明读写如何识别版本和避免重复转换。双写／双读会引入一致性与失败处理成本，不是默认答案；回填需要考虑重试、幂等、增量写入、校验与中断恢复。

每阶段说明前置证据、允许动作、成功／中止条件及负责主体或待分配责任。阶段边用可核实条件连接，不用日历日期代替消费者准备状态；已有期限与外部承诺保留并标明依据。

## 明确恢复与退役

分别判断回滚程序、回滚配置和恢复数据是否可行；旧代码未必能读取新数据，备份存在也不等于恢复已验证。为不可逆步骤说明所需授权、恢复方式、可接受损失／停机及尚待确认条件，不承诺无证据的零损失回滚。

退役需有消费者退出、存量处理、支持窗口和观测条件等与项目相关的证据，不能以“新版本已发布”自动删除旧路径。列出需要保持的监控及异常处置方式，不默认设置新基础设施。

## 交付可执行计划

沿用现有任务与迁移载体，关联阶段、检查和待决缺口，避免重复维护。实际执行另按授权与项目操作机制处理；本技能不自动运行迁移、删数据、切流、撤销支持或发布通知。计划足以执行，或剩余动作受明确外部缺口限制时停止细化。
