# 语义整合

判断多份结果是否共同实现有效目标，并在授权内整合。输入可以是分支、补丁、组件或多方产出；结果是可组合的行为或具体未解分歧，不以 Git 能合并作为正确性证明。

## 固定整合对象

明确要组合哪些结果、各自基于什么版本／契约，以及整合后的目标。读取相关约定和工作区状态，辨别未提交及无关工作。只有外部描述、无法取得实际资产时明确检查限制，不推断实现已一致。

确认允许分析、修改、合并还是交付。需要比较分支时优先使用读取或隔离工作区，保护现有工作；不自动重置、改写历史或清理冲突以获取“干净状态”。

## 沿共同边界检查

将组件的产出与下游实际接受的输入对应起来。重点核对共享状态含义、标识、单位、默认值、失败／重试与幂等语义、资源生命周期、事件顺序、依赖版本，以及对外兼容与交付承诺。

追踪跨边界的完整行为与关键失败路径，复用已有构建、契约检查和集成测试。单组件测试都通过仍可能组合失败；文本冲突消失、接口签名相同、各方“已完成”均不足以证明兼容。

区分实现缺陷、契约分歧和输入状态过期。能依据现有效契约消除的差异在授权内处理；无依据的产品取舍应提出推荐，而不是按最后修改、最新分支或某执行者自信程度裁决。

## 整合并核对

按最小有意义范围修改，保留无关工作，并运行与共享行为相称的检查。为整合后结果确认版本、输入和检查覆盖；没有现场环境时不能声称部署链路通过。

按请求更新已有共享契约及必要任务，报告已组合的结果、仍未解的具体分歧和实际检查。仅评审时给出定位和建议，不默认合并；有整合授权也不自动获得提交、推送、发布或修改支持策略的权限。

目标组合已得到相应证据，或剩余部分受明确决策／访问缺口限制时结束，不借整合全面重构其他模块。
