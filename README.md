# Agent 与人类协作的 SDLC

探索在人类与 agent 共同承担软件开发工作时，信息、产出物与工具应如何组织，并用本项目自身的工作方式实践这些设计。

## 要解决的问题

让人类与 agent 在有限上下文、不同权限和持续变化的系统中，能够理解目标、形成判断、协作行动并接续工作。

研究信息如何产生、供给、演进和被使用，并由此推导 Git、文档、任务系统、会话及记忆的职责。成果中的过程信息混杂是切入问题之一。

## 产出与交付状态

- 理论与规范：信息组织、上下文与协作机制，以及来源和案例。
- Codex 跨项目能力：将方法落实为可安装的技能，按需要封装为插件；实现任务尚未开始。

理论材料保存在独立 repo 中，不会自动进入其他项目的上下文。第二层需要解决分发、发现、加载和执行，并在另一个 repo 的新 session 中实际使用。

## 按任务进入

- 理解或扩展理论：先读理论体系，按需查看信息目录与案例。
- 处理明确任务：读相关成果和协作规则；不必通读信息模型与全部历史。
- 推进跨项目能力实现：从第二层任务计划进入。
- 查看理论建设的完成范围：读理论任务计划。
- 延续开放探索：查看探索材料中的未决问题。
- 调整协作行为：读工作流程，明确需要改变的行为。
- 回答历史原因：先定位相关成果，再按需查询 Git。

## 工作方式

从实际工作中的信息需要出发，再选择文件、Git、任务系统或其他载体。探索可以使用现有工具的新用法，也可以提出新的组织方式。

使用本项目暴露问题、修改设计；不以记录数量或工具复杂度衡量进展。
