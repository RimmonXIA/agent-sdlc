# Agent 与人类协作的 SDLC

研究人类与 agent 共同开发软件时，信息、产出物和工具应如何组织，并将方法落实为 Codex 技能。

目标是在有限上下文、不同权限和持续变化的系统中，减少重复解释、误读与协调负担。Agent 将过程说明混入代码和文档，是本项目的切入问题之一。

## 产出与入口

| 需要做什么 | 入口 |
|---|---|
| 安装或选择 14 项技能，查看调用和维护方式 | [使用说明](USAGE.md)；具体执行契约在各项 `skills/<name>/SKILL.md` |
| 了解已检查范围和局限 | [检查结果](checks.md) |
| 理解一项软件变更如何从讨论走到交付 | [整体工作方式](operating-model.md) |
| 理解概念、机制、取舍与工具职责 | [理论体系](theory.md) |
| 查理论依据与迁移限制 | [领域基础](foundations.md) |
| 按信息需要定位产出物及维护方式 | [信息模型](information-model.md) |
| 看具体情境中的应用 | [贯穿场景](examples/scenarios.md)、[兼容约束案例](examples/compatibility.md) |
| 继续尚未解决的问题 | [开放问题](inquiry.md) |
| 在本 repo 工作 | [协作规则](AGENTS.md)、[工作流程](workflow.md) |

14 项技能均可独立安装。技能分发通用方法和必要参考，不复制整套理论或个人授权；目标项目的事实、约束与运行状态从目标项目取得。已制作与实际收益是不同判断，检查范围见上述结果。

明确任务直接读取相关成果及依赖，不必通读全部材料。需要解释历史选择时，按文件查 Git；以实际需要选择文件、任务系统和其他载体，不以记录数量衡量进展。
